# SOUL 화면 업데이트 통합 계약

2026-10-05. 사용자 최신 요청과 기존 Qwen 설계/검사를 유지하며 화면만 갱신한다.

## 기준과 범위

- 화면 기준은 `jiwooks/SW-Festival`의 `feat/frontend-update` 커밋 `c0a09e2f51f8070dfec1a361eec0ff99f031dd32`다. 사용자 표현의 frontend-update 브랜치는 실제로 이 이름이다.
- 해당 화면 변경이 병합된 main `de5acf66ccced8571ba46dcda93acf44b6e06222`와 기존 `codex/soul-qwen-integration`의 공통 이력을 연결한다. 외부 모델 API/학습 작업을 병합하는 대신 확인한 프론트 변경을 Qwen API 계약에 맞춰 적용한다.
- 아이디어·타깃·편집·비교·대화·리포트·상태 화면과 아바타/카드/표시 타입 등 프론트 파일 16개를 검토했다. 다른 모델 API/가중치/추론/학습 구현은 읽거나 실행하지 않았다.
- 화면 시안의 고정 이름·나이·성별·가짜 후기·찬반 역할·관심사·고정 선택·고정 질문/가격은 모델 생성 결과나 고객 사실로 복사하지 않는다. 새 fine-tuning은 수행하지 않는다.

## 화면과 실제 데이터

| 항목 | 최종 연결 |
|---|---|
| 이름 가독성 | `text-base`가 배경색 토큰과 충돌해 흰 글자로 렌더링되던 원인을 제거. 이름/관련 제목에 크기 전용 유틸리티 사용 |
| 추천 타깃 | 생성 전부터 가상의 이름과 실제 추천 이용자 유형 표시. 이름 옆 별도 역할군/표시 선택기 없음 |
| 이름 유지 | 선택 당시 `display_names`를 서버에 저장하고 선택 타깃 ID와 카드를 연결. 예전 세션은 기존 이름과 세그먼트로 복원 |

| 아바타 | 새 SVG 얼굴 스타일. 이름으로 일관된 장식 선택; 나이/성별/고정 성향을 외모에서 추론하지 않음 |
| 공용 편집 | 타깃·비교 화면에서 `/targets/new?edit=...` 사용. 선택 전 후보는 이름/이용자 유형/상황/대안/조건 편집, 선택 후 카드는 기존 validator 경유 |
| 안전한 저장 | 이름+카드 변경은 검사가 성공해야 함께 저장. 중복/빈 이름은 거부. 대화가 시작된 불변 카드는 변경하지 않음 |
| 미리보기 | 후보를 편집하는 동안 바로 갱신. 다른 후보의 이름과 색상은 불필요하게 바뀌지 않음 |
| 아이디어 요약 | 타깃 화면에 실제 문제/설명/고객 유형, 대화 화면에 한 줄 소개를 표시. 고치기는 기존 기록을 보존하며 아이디어 초안을 새 입력 화면에 복원 |
| 비교 | 모두 미확인인 행과 반복 문구를 줄임. 판단 조건은 유지하며 근거/확인할 점/검사 결과는 펼쳐 보기로 제공 |
| 대화 | 기존 한 채팅창, 사용자 질문 → 독립 답변 → 조건 기반 상호응답 유지. 발화 번호는 실제 발화자 이름으로 표시; 원 인용/저장 내용은 변경하지 않음 |
| 리포트 | 동일 이름/색상 연결, 실제 세션 기반 8개 섹션·근거·인용·미확인·이어 묻기 유지. 반복 설명을 줄이고 비어 있는 질문 상태 설명을 정확히 표시 |

사용자 이름은 사실 근거나 페르소나 경험으로 승격하지 않는다. 후보 이름은 인물 구분을 위한 표시값이며 답변이나 가격을 하드코딩하지 않는다. 모르는 경험/예산/조건은 UNKNOWN으로 남긴다. Mock은 화면 시험에만 명시적으로 사용한다.

## 2026-10-05 재점검: 화면 배치와 필드 의미

사용자가 지적한 화면 차이를 기준 브랜치의 실제 컴포넌트와 다시 대조했다. 입력 화면은 **기본(한 줄 소개 + 사업 분야/고객 유형 같은 행) → 아이디어(설명/문제·차이 같은 행) → 접힌 배경·수익 모델 → 실현 계획·자료** 순서로 옮겼다. 표시 라벨의 Q 번호를 없애고, 네 필수 칸과 문자 한계를 표시한다. 기존 브라우저 초안의 문구를 자동 이관하며 이전 API 기록의 누락 필드는 기본값/UNKNOWN으로 해석한다.

모델 입력도 화면 뜻에 맞게 분리했다. 첫 설명은 solution, 두 번째는 problem/value proposition, 고객 유형은 명시적 customer_type, 창업자 역량은 별도 founder_strength다. 고객 유형만으로 특정 이용자·경험을 만들지 않는다. 기존 기록처럼 설명 칸이 없을 때만 이전 문제·차이 문구로 설명을 대체한다. 파일 버튼은 TXT/MD/CSV의 관련 원문을 L0으로 넣으며, 자료의 실제 성격을 확인한 후 근거 수준을 올릴 수 있다. PDF 텍스트 추출은 구현되어 있지 않아 원문 발췌 칸을 안내한다.

타깃 화면에는 원본과 같은 가로형 **읽은 내용**, 추천/수정 헤더, 직접 만들기 칸과 하단 선택 띠를 연결했다. 추천 카드의 이름/이용자 예시/상황/현재 대안/확인할 점/추천 이유/근거 수준을 복원하고 각 인물의 지정색을 카드 상단과 상황 배경에도 사용한다. 원본 시안의 관심사·걱정·나이·성별·한마디는 이 단계에서 Qwen이 확인하지 않은 사실이므로 빈 값으로 채우지 않는다. 비교 화면의 강조 배너는 실제 생성 카드의 판단 기준이 서로 다를 때만 차이를 표시한다. 채팅·리포트는 기존 Qwen 상태/발화/근거 연결을 유지한다.

원본 시안은 후보 다섯 명을 예고하지만 Qwen 추천 계약은 6–8명 생성 후 중복 제거한다. 실제 수와 충돌하는 약속을 없애고 수량 없는 설명을 사용한다. 최대 세 명 선택 정책은 유지한다. 비교·채팅·리포트에서 가상 인물의 이름/색상은 같은 타깃 ID를 따라간다.

## 검증과 배포

최종 검사와 실제 Qwen 실행 범위는 `docs/SOUL_VERIFICATION.md`와 `STATUS.md`에 기록한다. 기존 사용자 DB/17개 원 기록을 시험 데이터로 쓰지 않는다. 모델, DB, 실행 로그, 원본 PDF는 공개 브랜치에서 제외한다. GitHub 업데이트는 기존 `codex/soul-qwen-integration` 브랜치와 PR #5를 사용한다.
