# Persona Studio v5 — 기본 채팅과 내용 중심 상호작용

설계 고정: 2026-10-04. 구현·검증 결과는 `STATUS.md`에 별도로 기록한다. 이 문서는 [v4 설계](13_PERSONA_LOUNGE_DESIGN.md)의 표시 선택, 질문당 4회 응답, 대화 종료와 리포트의 결합을 대체한다. NSona 67쪽 대응과 문헌의 정확한 서지는 [14번 문서](14_NSONA_RESEARCH_AUDIT.md)에 유지한다.

## 사용자에게 보이는 계약

- 생성·선택한 페르소나는 **가상 이름 + 예시군(segment)**으로 표시한다. 역할 배지와 표시 방식 선택칸은 없앤다. 역할은 판단에 필요한 내부 카드 정보이며 프로필의 상세 정보에서 확인할 수 있다. 이름은 별칭이고 추론 근거가 아니다.
- 페르소나 선택이 끝나면 하나의 공개 대화창과 **기본 메시지 입력칸**이 바로 보인다. 별도 ‘추가 질문’ 화면이나 입력칸은 만들지 않는다. 추천 질문은 같은 입력칸에 넣어 사용자가 전송하게 한다.
- 선택된 상태에서 `/ask`로 첫 메시지를 바로 보낼 수 있다. 필요한 독립 사전 의견을 한 번 수집하고 공개 대화를 시작하며 추천 질문 생성은 채팅 시작의 필수 작업이 아니다. 대화 중에도, 답변 묶음이 끝나도, 리포트를 만든 뒤에도 같은 입력칸에서 이어서 보낸다. 작성 중인 메시지는 화면 갱신이나 폴링으로 덮어쓰지 않는다.
- 기본 메시지는 선택한 전원에게 열려 있다. 세 명을 선택했다면 세 명 모두 자기 조건에 따른 기여를 한 번 이상 한다. 특정 이름을 지목하면 먼저 답할 사람의 우선순위로 사용한다. 관계없는 참여자에게 새로운 사실이나 억지 반대를 만들게 하지 않는다.
- 사용자 메시지에 대한 응답 묶음이 끝나는 것과 세션이 영구 종료되는 것은 다르다. UI에는 ‘대화가 끝났으니 추가 질문’이라는 별도 단계 대신 ‘메시지를 입력하세요’를 유지한다. 리포트 버튼은 현재까지의 내용을 정리하는 별도 작업이다.

## 확인한 빈약함과 수정 범위

아래는 수정 전 v4 코드 감사 결과다. 숫자는 연구 결과가 아니라 실제 구현의 제한이었다.

|---|---|---|---|
| `guided.ask` | `count < 4`, interactive에서 다른 사람 한 명만 추가 | 두 명에서 끊겨 세 번째 관점이 사라질 수 있음 | 전원 참여를 먼저 보장하고, 목적 있는 후속을 남은 예산으로 실행 |
| `adaptive.reaction` | `depth >= 3`이면 종료 | 하나의 정정·질문 연쇄만으로 전원 참여가 막힐 수 있음 | 참여 범위와 개별 연결의 깊이를 분리; 질문·정정 수신자가 답할 기회 보존 |
| `InteractionAnswer.model_json_schema` | 공개 `content` maxLength 240 | 카드→원인→상충 조건을 설명할 공간이 부족함 | 스키마는 문맥/출력 안전 상한, 프롬프트는 정보의 충분성을 우선; 140자/240자 압축 목표 제거 |

| `guided.PUBLIC_LIMIT` | 세션 전체 공개 60발화 상한 | 같은 채팅창에서 계속 질문하는 계약과 충돌 | 비용은 메시지당 상한으로 통제; 오래된 문맥을 요약하여 세션을 이어감 |
| 완료 뒤 `guided.ask` | 매 메시지 후 `generate_report` | 사용자에게 보이지 않는 추가 LLM 호출과 지연 | 메시지는 대화만 생성; 리포트는 명시적 요청 시 현재 transcript의 snapshot |
| `guided.finish` | 첫 closing/post 존재 여부로 중복 방지 | 새 메시지 이후 오래된 최종 의견이 재사용될 수 있음 | snapshot을 transcript revision에 연결; 이후 대화는 가능하고 기존 리포트는 이전 시점임을 표시 |
| `services.generate_report` | 발화 앞140자/이유60자만 발췌, 긴 기록은 최대30턴 | 긴 응답의 뒤쪽 유보·실패 조건이 잘려 확정적 결론으로 보일 위험 | 제한된 발췌임을 표시하고 이유/미해결 조건과 화자 균형을 보존; 실제 리포트 의미 검토에 잘린 조건 점검 포함 |
| context/quoted peer | 자신의 최근4/공개최근6, 요약·인용 100~180자로 절단 | 원질문과 판단 조건이 사라져 다른 주제의 불확실성에 붙잡힐 수 있음 | 원질문 매턴 유지, 현재 답변 대상의 부모 발화 우선 보존, 오래된 주제는 귀속 요약 |
| 안전 문장 교정 | 일부 확정 구매·경험 표현을 정해진 문장으로 교체 | 방어가 자주 발동하면 대화가 실질적으로 비슷해짐 | 원문/flag를 보존하고 해당 카드의 조건부 판단으로 교정; UNKNOWN만 말하도록 유도하지 않음 |

타깃 수, schema, evidence gate, 안정적인 ID, 재개 cursor 같은 **구조 규칙은 필요**하다. 바꾸어야 할 것은 짧은 답변/부분 참여를 강요하는 제한과 특정 주장을 대신 생성하는 문장이다. 모델이 생성해야 할 구매 판단·찬반·상호작용 내용은 응답 fixture로 대체하지 않는다. 테스트의 synthetic fixture는 실제 Qwen 검증과 분리한다.

## 한 메시지에 대한 유연한 대화

### 1. 원질문과 참여 범위

사용자 메시지를 `thread.question`으로 저장하고 모든 공개 생성에 `dialogue_goal`로 전달한다. ‘어떤 가격 조건이 필요한가’를 물었는데 이전의 ‘기관 협력 여부’만 재질문하는 응답은 목적 이탈이다. 입력이 모호하면 필요한 확인을 짧게 묻되, 카드에서 판단 가능한 범위도 함께 설명한다. 입력 길이 한도는 UI 카운터와 API가 같은 값을 사용한다.

### 2. 전원의 첫 기여

controller는 아직 이 질문에 기여하지 않은 참여자를 우선한다. 관련성, 직접 지목, 조건 차이, 미해결 질문, 최근 발화 패널티로 순서를 고르며 이름·성별·교대로 정한 찬반에는 점수를 주지 않는다. 각 사람은 원질문에 먼저 답하고, 자기 카드의 대안·노출 상황·의사결정 조건에서 필요한 차이를 설명한다. **첫 기여는 같은 질문의 공개 동료 응답/부모를 문맥에 넣지 않고 독립 생성한다.** 세 답변은 같은 공개 채팅창에 차례대로 출력한다. 다음 교차 응답 단계에서 공개 부모를 보여 주고 실제 조건을 비교하므로 개인 답변만 받고 끝나는 구조가 아니다.

이 변경은 v5 첫 실제 Qwen 시험에서 한 사람의 ‘무료 인큐베이터’ 대안을 다른 두 사람이 자기 대안처럼 복사한 실패를 반영한다. 첫 기여를 독립 생성하고 매 그룹 턴에 `own_decision_frame`으로 자신의 대안·역할·판단 가설을 명시한다. 실패 trial은 `examples/qwen_continuous_chat_pre_fix/`에 보존하며, 보완된 코드의 실제 실행 결과는 별도 release 증거로 평가한다. 문맥 분리가 역할 도용을 완전히 제거한다고 주장하지 않는다.

그 이후 실제 출력에서도 교차 응답의 이름 오귀속, 동료의 선호/판단 가설 도용, 카드에 없는 대안의 가격·기능 한계를 사실처럼 설명하는 실패가 남았다. 그 trial은 `examples/qwen_continuous_chat_independent_trial/session.json`에 보존했다. 그래서 `chat` grammar는 첫 필드에 `own_basis`를 출력하도록 강화했다. `role`과 `expected_alternative`는 **해당 카드 값 그대로의 const**이며 자연어 답변보다 먼저 생성해 자기 관점을 유지하도록 유도한다. 프롬프트도 자신의 rule을 우선하고 없는 가격·품질·기능·불만족은 ‘만약 …라면’ 조건으로만 논의하게 한다. 이 metadata는 모델/카드의 일치 확인에 도움이 되지만 **자연어 충실성이나 실제 고객의 역할·대안을 증명하지 않는다**. 카드 자체가 L0 가설이면 const도 L0 가설이다.

const 이후 trial에서도 ‘저는 정보 제공자’처럼 다른 역할을 자기 역할로 설명하거나 자기 이름에 ‘님’을 붙여 동료처럼 부르는 표현이 남았다. 최종 입력은 카드마다 반복되는 `r1/r2`를 모델이 같은 rule로 오인하지 않도록 **소유자를 붙인 ID**(`p1:r1`, `p2:r1`)를 사용한다. 입력용 카드 복사본만 변환하므로 immutable 원본과 저장된 local ID는 그대로다. `own_decision_frame`에는 자신의 rule의 trigger/value/tradeoff/conditional_choice 전체를 보내고 공개 부모의 rule도 해당 peer의 소유자 ID와 설명으로 구분한다. 응답의 자기 소유자 ID만 local ID로 되돌리고 검증한다.

고정 찬성/반대/중재 역할을 부여하지 않는다. 조건이 같으면 동의하면서 적용 범위를 설명한다. 주제와 자신의 상황이 무관하면 그 범위를 말하고 다른 사람의 역할을 대신 맡지 않는다. 선택한 persona의 immutable core는 바뀌지 않는다.

### 3. 목적 있는 후속

후속의 목적은 네 가지다: **조건 비교, 판단의 이유 확인, 오해 정정, 결정/실험 조건 구체화**. 미응답 지명 질문이나 정정 요청은 해당 사람에게 연결한다. 주장에 응답할 때는 정확한 공개 부모의 ID와 **전체 공개 본문**을 전달한다. 그 부모에는 실제 peer card의 `speaker_alias`/`hypothetical_role`/`expected_alternative`를 붙여 자신의 frame과 구별한다. 교차 응답 모델에는 다른 공개 recent/older buffer를 비우고 이 `required_parent`만 관찰 대상으로 전달한다. 전체 대화 기록과 controller의 thread 연결은 저장하며, 제한된 입력이 전체 동료 관점을 모두 보았다는 의미는 아니다. 모든 후속은 원질문과 관계가 있어야 한다. 다른 페르소나에게 실제 시장 자료를 만들어 달라고 묻는 순환은 이어가지 않는다.

기본 `auto`/`interactive`는 선택한 전원의 첫 기여를 보장한 뒤, **관련된 자기 카드의 조건이 있는 참여자만** 교차 응답 기회를 한 번씩 둔다. 참여 수를 n이라 하면 기본 범위는 **2×n**이며, 명시적인 확인 질문/정정에 대한 확장은 **최대 3×n**이다. 세 명일 때 약 6~9개 공개 발화를 수용한다. 일부 참여자의 관련 조건이 UNKNOWN이면 그 사람의 첫 답은 유지하지만 근거 없는 비교 발화를 늘리지 않는다. 모두의 관련 카드 정보가 UNKNOWN이어서 근거 있는 확장이 없거나 같은 내용만 반복되면 전원의 첫 기여 후 조기 반환한다. 이는 연구가 입증한 최적 숫자가 아니라 로컬 비용 설계다. 상한을 채우기 위해 같은 질문이나 인위적인 이견을 만들지 않는다. 남은 연결은 해결된 척하지 않고 보존한다. 기존 연동용 `direct` API는 한 사람의 직접 답변 동작을 유지하며 기본 채팅 UI의 세 사람 대화와 구분한다.

### 4. 내용을 깊게 하는 방식

공개 응답에는 다음 중 원질문에 필요한 요소를 연결한다. 양식 제목이나 일정 문장 수를 매번 노출할 필요는 없다.

- **직접 답:** 지금 질문에서 자신은 무엇을 판단하는가.
- **자기 조건:** 어떤 대안·역할·문제 노출·rule을 사용했는가.
- **원인과 상충:** 왜 그 조건에서 유용하거나 어려운가. 시간/비용/신뢰/전환 부담을 어떤 조건에서 다르게 보는가.
- **조건부 해석:** 조건 A라면 무엇을 비교하고, 조건 B라면 어떤 판단을 보류하는가. 실제 예산·사용 빈도가 없으면 숫자를 발명하지 않는다.
- **동료와 연결:** 동료의 어떤 조건이 자신에게도 적용되거나 적용되지 않는가. 무엇을 확인하면 입장이 바뀌는가.
- **실제 확인:** 누구에게 무엇을 묻거나 어떤 행동 자료를 보면 이 가설을 좁힐 수 있는가.

‘예산이 UNKNOWN이다’는 올바른 사실 경계다. 그러나 그 다음에 예산/대체 비용/승인 주체가 왜 판단을 바꾸는지 가설로 설명할 수 있다. 빈 필드를 채우는 것과 의사결정 구조를 설명하는 것을 구별한다. Timeline 사건은 제공된 원문이 있을 때만 사용한다. 보이지 않는 내적 사고 과정이나 실제 심리를 추출한다고 주장하지 않는다.

### 5. 반환과 다음 메시지

전원 참여와 관련된 후속을 끝냈거나 예산을 소진하면 현재 묶음만 종료하고 입력칸을 다시 활성화한다. 매번 마지막 페르소나의 의견에 모두 동의시켜 끝내지 않는다. 미해결 조건/불일치는 thread에 남긴다. 다음 메시지는 새 thread이며 자기 상태와 관련 있는 공개 이력은 유지한다. 재전송/중단 재개에는 같은 cursor를 사용하여 이미 공개한 발화를 중복 생성하지 않는다.

## 근거가 지지하는 것과 지지하지 않는 것

- 인간 focus group은 참여자 간 질문·비교·설명의 상호작용을 자료 생성 방법으로 사용한다. 이를 참고해 순차적인 개인 답변 뒤 구체적인 조건 비교를 설계했다. **가상 모델 세 명이 실제 고객 세 명과 같은 검증력을 갖는다는 뜻은 아니다.** [Kitzinger, BMJ 1995](https://www.bmj.com/content/311/7000/299).
- 다음 화자의 지명과 국소적인 턴 조직, 질문–답변 연결과 확장은 대화 분석의 기반이다. 전원 참여라는 제품 계약과 개별 질문 연결을 별도로 관리한다. **6~9턴, 답변 글자 수, 순서 점수의 계수는 고전 논문에서 증명된 값이 아니다.** [Sacks, Schegloff & Jefferson, 1974](https://pure.mpg.de/pubman/item/item_2376846_3/component/file_2376845/Sacks_1974_simplest_systematics.pdf), [Schegloff, Cambridge 2007](https://www.cambridge.org/core/books/abs/sequence-organization-in-interaction/adjacency-pair-as-the-unit-for-sequence-construction/9AFC5658125C316C1A0FDE9DE4027C6D).
- 대화의 화자 정보와 reply dependency를 이용한 연구는 뒤섞인 문맥을 구조적으로 다루는 근거다. 현재 목적/부모 발화를 보존하고 스레드 경계를 추적한다. 이 논문들의 Ubuntu IRC/응답 선택 성과를 우리 창업 인터뷰의 정확도라고 옮기지 않는다. [Ma et al., ACL 2022](https://aclanthology.org/2022.acl-long.23/), [저자 코드](https://github.com/xbmxb/StructureCharacterization4DD), [Jia et al., EMNLP 2020](https://aclanthology.org/2020.emnlp-main.150/), [저자 코드](https://github.com/JiaQiSJTU/ResponseSelection).
- 다음 화자 선택은 무엇을 말할지의 생성과 별도 평가해야 한다. heuristic의 관련성·지명·참여 점수는 운영 정책이고 전용 NSP 모델의 연구 성능을 상속하지 않는다. 인간의 실시간 발화 시점을 모델이 안정적으로 추정한다고 가정하지 않아 사용자 전송/완성 응답을 경계로 삼는다. [Hilgert & Niehues, ICNLSP 2025](https://aclanthology.org/2025.icnlsp-1.7/), [Umair et al., EMNLP Findings 2024](https://aclanthology.org/2024.findings-emnlp.909/).
- 다중 LLM 대화는 동조와 persona 불안정성을 일으킬 수 있고, 의견을 지키며 논쟁하라는 지시도 불안정성을 높인 결과가 있다. 따라서 ‘더 오래 논쟁하면 좋아진다’는 가정을 쓰지 않는다. private baseline, 자기 카드 우선, 근거 있는 입장 수정, 순환 종료가 필요하다. 이 연구는 문화 persona 시뮬레이션이며 사업 고객 검증의 직접 결과는 아니다. [Baltaji et al., C3NLP 2024](https://aclanthology.org/2024.c3nlp-1.2/).

## 로컬 모델·속도·리포트

Qwen 한 개를 공유하고 세 사람의 owned/private context를 분리한다. 매 질문마다 별도의 moderator 모델이나 judge를 상시 호출하지 않는다. JSON metadata로 제안된 act/수신자와 controller의 참여·반복·예산 검사를 사용한다. 출력 길이를 늘린 만큼 첫 묶음 생성은 오래 걸릴 수 있으므로 실제 생성 상태와 완료된 발화를 차례대로 표시한다. 가짜 typing 지연은 넣지 않는다.

대화 출력과 safety/schema 상한은 구별한다. 충분한 원인·상충 설명이 가능하도록 140자 목표와 240자 grammar 상한을 제거한다. 공개 내용의 schema 안전 상한은 900자, 턴당 기본 생성 예산은 640token이다. 정해진 글자 수를 채우거나 긴 응답을 높은 품질로 자동 판정하지 않는다. `llama.cpp`의 실제 tokenizer를 통한 입력+출력 예산 확인은 계속 유지한다. 첫 기여에서는 현재 질문의 동료 응답/부모를 제외한다. 교차 응답·정정에서는 공개 recent/older buffer 대신 `required_parent`의 전체 본문·이름·역할·대안·peer rule을 구별해서 전달한다. 원질문과 자신의 `own_decision_frame`/card/rule은 모든 그룹 턴의 우선 문맥이다. `own_basis`는 자기 카드 값의 const이며 형식적 일치만 보장한다.

공개 턴의 own 입력은 현재 원질문의 독립 기여 최대1개, 이전 자신의 가설을120자로 발췌한 최대2개, 자기 private pre baseline으로 제한한다. state는 stance만 보내고 이전 생성 reasons를 안정적인 선호·인물 특성으로 다시 주입하지 않는다. 발췌에는 가설 표시를 유지한다. 전체 이력과 상태 원본은 저장하므로 이 제한은 기록 삭제가 아니다. packing 후 실제 남아 있는 공개 ID만 reply enum에 허용하며 private pre/post는 다른 사람에게 전달하지 않는다.

### 좁은 역할·귀속 방어와 비교 보류

반복/구매·경험 overclaim 검사에, 명시적 자기 지칭(저는/제가/제 역할은) 뒤 좁은 범위의 다른 역할 선언과 교차 응답에서 자기 이름+‘님’ 표현 검사를 더한다. peer의 조건을 언급하는 것과 자기 역할 선언을 구별하는 제한적 lexical guard다. 문장 전체의 의미, 모든 대안 도용, 올바른 동기 해석을 검증하는 도구가 아니다.

문제가 감지되면 반복/overclaim과 합쳐 **최대 한 번** LLM 수정한다. 여전히 역할·응답 대상 불일치가 남으면 raw 생성 내용과 `*_withheld` flag를 저장하고, 같은 원질문에서 자신이 이미 생성한 독립 판단을 유지하며 새 비교를 보류한다. baseline이 없으면 자기 rule의 조건부 선택으로 보류한다. 서버가 새 시장 판단이나 찬반을 대신 작성하지 않는다. UI에는 ‘응답 귀속을 확인하지 못해 앞선 독립 의견을 유지했습니다. 새 비교는 보류합니다’라는 안내를 붙인다. 보류된 비교를 유용한 새 인사이트나 성공적인 상호정교화로 집계하지 않는다.

리포트는 생성 당시 공개 transcript revision을 기록한다. `/ask` 후에는 WAITING으로 돌아가며 기존 리포트는 이전 시점의 snapshot이다. 오래된 리포트를 현재 결론으로 표시하지 않고 재요청 전까지 보존한다. `/finish`는 리포트 요청으로 사용하며 매번 공개 closing 세 턴을 강제하지 않는다. 실제 보고에 필요한 독립 사후 의견은 해당 snapshot 기준으로 갱신하되 이력이 없다는 이유로 새 경험을 만들지 않는다. 같은 revision에 대한 재요청은 기존 snapshot을 돌려주며 모델을 다시 호출하지 않는다. 보고용 발췌는 원문의 완전한 의미를 보장하지 않으므로 조건/이유/미해결 항목을 함께 보존하고 발췌·제외 정보를 남긴다. 보고의 조건부 합의가 구매 확정으로 바뀌지 않았는지 실제 Qwen 결과를 원문과 대조한다. 자동 인터뷰 v3/통제 실험 v2의 재현용 동작은 별도로 유지한다.

## 실행 가능한 검증 기준

1. **구조 회귀:** 1/2/3명 선택, 전원 첫 기여의 동료 group/부모 비노출, 교차 응답의 공개 부모 보존, 자신의 조건이 없는 참여자의 불필요한 비교 제외, 지명·정정 우선, 올바른 thread, private 격리, immutable core 불변, 신규/완료/중단된 세션에서 같은 composer, 중단 cursor 재개와 중복 방지, 메시지마다 리포트 호출하지 않음, snapshot 이후 stale 판별을 테스트한다.
2. **실Qwen 시나리오:** 서로 다른 대안을 가진 세 persona에게 (a) 가격/대안 비교, (b) 앞선 답의 특정 조건 확인, (c) 관련 있지만 다른 사업 질문을 순서대로 보낸다. 공개 화자 집합과 연결을 점검하고 사람은 원질문 답변, 카드 조건, 원인/상충, 조건부 결정, 동료의 실제 발화에 대한 응답, 다음 확인의 구체성을 검토한다. 각 발화의 ‘내 대안/역할/우선 조건’을 실제 카드/rule과 대조해 다른 사람의 대안·선호 도용을 검사한다. 인용한 이름/주장의 최초 작성자를 `reply_to`의 실제 발화자와 대조한다. `own_basis` const, 문장 수/글자 수나 `reply_to`만으로 이 의미 품질을 통과 처리하지 않는다.
3. **실패 분리:** 단순 연결 성공·구조 검사·PSV-9 judge·사람의 대화 품질 검토·실제 고객 Theme Recall/False Insight는 서로 다른 결과다. 긴 Qwen transcript가 남아도 human dataset이나 실제 고객 기준이 없으면 성능 검증 완료로 표시하지 않는다.
4. **내용이 부실한 실패:** 세 명이 같은 UNKNOWN 한 문장만 반복, 카드와 무관한 찬반, 앞선 역할/대안 도용, 서로에게 없는 시장 자료 요구, 원질문을 버린 반복, 정정에 대한 답 없이 반환, 실제 경험/가격/구매 확정 날조를 표기한다. 반복 교정은 최대 한 번으로 제한하며 원문과 flag를 남긴다.
5. **비용/문맥:** 실제 max prompt+reserved completion이 서버 context 이하인지, 질문 묶음의 실제 token/call 수와 latency, 질문 뒤 report call 여부를 기록한다. 4B/9B의 구조·품질·지연은 같은 질문과 예산에서 비교하기 전에는 우열을 단정하지 않는다.

이 설계는 출판된 방법과 관찰을 바탕으로 한 제품/구현 가설이다. 선택한 이름+예시군의 UX 우월성, 6~9턴의 최적성, 실제 창업 인사이트 정확도는 이번 문헌 검토만으로 입증되지 않는다.

### 실제 출력 점검에서 남긴 구체 실패

2026-10-04 실행 중인 DB를 읽기 전용으로 조회한 기록이며 이후 `examples/qwen_continuous_chat_independent_trial/session.json`에 보존됐다. 아래 발화들은 `own_basis=None`이므로 **own_basis/부모 문맥 강화 전 기록**이며 최종 보완의 성과로 사용하지 않는다. 이는 생성 내용 감사이고 실제 고객 기준 human validation 결과가 아니다. `examples/qwen_continuous_chat_final/`의783.115초/3질문/20공개 발화/2snapshot 및 동일 snapshot 캐시 결과도 **최종 lexical guard/rule 소유자/own 이력 방어 이전 trial**이다. 현재 코드의 추가 실Qwen·UI 결과는 `examples/browser_continuous_session.json`과 `browser_continuous_verification.json`에 별도 기록했다. th5만 최종 persona 입력 보호의 실제 출력이며 이전 trial 이력이 섞인 전체 저장 기록을 최종 품질로 사용하지 않는다. 최종 결과/파일 범위는 STATUS를 따른다.

- `u6/p1`: 자신의 정부 창업 지원 프로그램 대안에 ‘비용은 낮음/표준화된 질문으로 니즈 파악 어려움’을 덧붙였다. 카드에 그 가격·문제·기능 정보가 없으며 앞서 제공된 사실로 확정하면 안 된다.
- `u8/p2`: `reply_to=u6`의 작성자는 김하늘/p1인데 자연어에서는 ‘박시온의 주장’으로 설명했다. 유효한 ID가 있다는 것과 제대로 된 주장 귀속은 다르다.
- `u9/p1`: p2의 ‘기능 대비 비용 효율성/습관 변화 비용’을 자신의 우선 판단으로 가져왔다. 자기 rule의 근거와 입장 수정 이유가 필요하다.
- `u13/p3`, `u16/p3`: 자신의 이름을 다른 참여자처럼 사용하거나, 최초 p2가 제안한2주 제한 테스트를 박시온의 제안처럼 귀속했다. 2주 테스트는 모델이 제안한 실험 가설이며 제공된 관찰이나 이미 시행한 PoC가 아니다.
- `u21/p2`: 개인 구독/기관 라이선스라는 새 원질문에서도 카드 밖 기관 데이터 공유·보안·협력 투명성에 고착했다. 자신의 비용/기능·전환 rule에 새 질문을 연결해야 하며 전 thread의 생성된 전제가 새 사실이 되어서는 안 된다.

후속 보완은 독립 첫 기여, 자기 조건의 const 선출력, 부모 귀속과 rule 소유권, 좁은 lexical guard/비교 보류와 own 이력 오염 제한이다. 현재 코드의 실제 th5는6개 발화/7콜로 완성됐지만 반복·모호한 대안 귀속·이전 가설 고착이 남았다. 검증 JSON에 그 의미 한계를 그대로 기록했다.


### 최종 리포트 보완

실제 갱신 보고에서 ‘모든 참여자는 … 동의’라는 문장이 p2/p3 발화만 인용했다. 서버는 보편 합의 문장에 선택 전원의 인용이 있는지를 추가 검사한다. 없으면 새 합의를 만들지 않고 범위 부족으로 보류하며 원문과 누락한 persona ID를 `dialogue_runtime.report_claim_audits`에 남긴다. 새 생성과 동일 revision 캐시 양쪽에 적용하며 추가 모델 호출은 없다. 전원 인용은 필요조건이며 같은 조건에 실제 동의했는지의 충분조건은 아니다. 조건의 의미를 사람/Gold 기준으로 평가하는 후속 검증은 남아 있다.

최종 실제 결과는 STATUS와 `examples/browser_continuous_verification.json`, 회귀 결과는 `examples/test-results-v5.txt`를 기준으로 한다. 자연어의 규칙 ID는 정상 채팅/인용/보고 표시에서만 읽기 쉬운 표현으로 바꾸며 원본 응답·감사 metadata·다운로드 JSON은 보존한다.
