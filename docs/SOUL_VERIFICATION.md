# SOUL 통합 검증 기록

2026-10-05. 소프트웨어 실행 검증과 고객/모델 성능 평가를 구분한다. 모든 새 실행 시험은 별도 합성 아이디어·DB를 사용했다. 기존 사용자 세션을 테스트 입력으로 재사용하지 않았다.

## 환경·원본

- 프론트 기준: `jiwooks/SW-Festival` main `9f4337ede0b42bb4eef588c232165165112767fa`. 다른 프론트 브랜치는 파일 목록 비교만 수행했다.
- 보존한 Qwen 코드 기준: 기존 로컬 Persona Studio `ccb276b`.
- 기존 Qwen3.5-4B Q4_K_M 약 2.74GB, llama.cpp b11146/7fe450e19, Vulkan, context 8192/parallel 1. 이번에 가중치를 다운로드·혼합·재학습하지 않았다.
- Node.js 및 Python 3.12, Next.js 16.3.6/React 19.2.8. 공식 npm 패키지로 프론트만 설치했다.
- SOUL 보고서 PDF 전체 1페이지와 정적 HTML 전체를 검토했다. 원본 샘플 주장은 실행 데이터로 사용하지 않았다.

## 자동검사

최신 실행에서 다음 검사가 통과했다. 재실행 명령은 README 및 GitHub CI에 기록한다.

- backend pytest: **184 passed**, 약 51초(2026-10-05 화면 재점검 후 실행).
- Node: 한국어 formatter 33개 + 프론트 API·세션 경계 19개 + 채팅 표시 5개 + 이름/선택 연결 5개 + 리포트 SSR 10개, **총 72 passed**.
- 전체 TypeScript 검사와 ESLint 검사 통과.
- 최종 Next.js production build 성공: 전체 17개 화면/경로 생성, TypeScript 검사 포함.
- production 의존성 `npm audit`: 0건. 개발 의존성의 upstream ESLint 5개 high 경고에 대한 범위와 제한은 STATUS에 기록한다.

API·세션 경계 검사는 메모리 내 mock fetch/timer/localStorage, 리포트 SSR 검사는 합성 JSON을 사용한다. 한국어 정리는 일반 표시문만 대상으로 하며 원 인용·ID·URL·내보내기 보존을 검사한다. 늦은 폴링 응답의 덮어쓰기, 세션 전환 중 이전 작업의 응답, HTTP 404 외의 잘못된 세션 대체, 실제 대화 방식의 헤더 표시도 검사했다.

화면 재점검에서는 실제 `:8000/new`에서 번호 없는 네 필수 문항과 기본·아이디어·실현 계획 카드의 순서를 확인했다. `:8000/targets`에서 세션의 실명 표시, 이용자 예시, 색상 상단선/상황 틴트, 현재 대안·확인할 점·근거 칩을 확인했다. `:8000/compare`와 `:8000/chat`은 읽기만 했고 기존 대화를 새로 생성하거나 사용자 세션을 시험에 사용하지 않았다. 별도 저장 없는 Qwen 추천 호출은 새 문제/해결/고객 유형 입력으로 6명을 반환했다(147.8초). 이는 단일 합성 연결 시험으로 실제 타깃 적합성 검증은 아니다.

## 실제 Qwen 및 화면

1. 합성 서점 예약 아이디어에서 실제 Qwen 추천·semantic review: 검사/중복 제거 후 5개 WHO 타깃, 사용자가 선택한 3개 typed card와 별도 validator.
2. private pre 3개, 사용자 질문에 모든 참여자의 독립 기여 + 동료 조건 응답 6개, private post 3개. core fingerprint 변화 없음.
3. 기존 8개 리포트 섹션과 동적 화면 projection, 근거 발화 참조, 같은 revision 리포트 재조회에서 모델 재호출 없음.
4. 실제 브라우저: 입력 글자 수·Q3/Q4 제목, 최대 3개 선택/4번째 제한, 카드 비교, 공개 말풍선만 있는 단일 채팅창, 리포트 쟁점·조건부 반응·출처 상세.
5. JSON 내려받기: 저장 파일의 session ID·공개 발화 수·sources 배열 확인. 리포트에서 이어 묻기는 자동 전송 없이 기존 입력칸에 초안만 채움.
6. 초안을 전체 참여자 질문으로 바꾸어 같은 세션에서 다시 전송: 독립 기여 3개 + 상호 응답 3개 추가, 이전 리포트 snapshot 6 유지/stale true, 갱신 완료 후 12개 공개 발화·2개 질문·stale false.
7. 같은 세션의 세 번째 질문까지 저장 후 브라우저의 리포트 업데이트 실행 완료: **3개 질문·18개 공개 발화, revision 18/stale false**, COMPLETE/error 없음, 원래 8개 섹션 유지. 근거 없는 수치가 포함된 인터뷰 질문은 미확인으로 옮기고 설명을 표시했다. 안전한 질문이 없을 때 임의의 질문으로 채우지 않았다.

첫 실제 Qwen 실행 선택부터 리포트까지 **336.82초**(추천 시간 제외). 한 합성 샘플의 기능 실행 시간이며 모델 간 속도/품질 비교가 아니다. 별도 mock smoke는 타깃 6개·카드 3개·공개 6개·리포트 8개로 성공했고 **1.811초**가 걸렸다. 두 측정은 같은 종류의 모델 성능 비교로 해석하지 않는다.

## 품질 검사에서 발견한 점

Qwen이 카드·사용자 입력에 없는 빈도 숫자를 만들어 후속 답변으로 재사용하는 사례를 발견했다. 프롬프트와 단위 수치 출처 검사를 보완하고 재생성/보류 및 원문 감사 경로를 추가했다.

근거 없는 숫자를 대화 문맥에 섞은 최신 독립 점검은 실제 Qwen **1회 호출·14.706초**로 성공했다. persona core는 변경되지 않았으며 `invalid_numbers_published=false`, `flags=[]`였다. 이 실행에서는 허용되지 않은 숫자가 공개 답변에 나타나지 않았다. 한정된 출처 검사와 한 샘플의 결과이며 모든 환각·의미 오류를 검출하는 성능 평가가 아니다. 원문 기록은 수정하지 않으며 AI 발화를 실제 고객 근거로 승격하지 않는다.

## 보존·배포 범위

원 Persona Studio의 **기존 17개 세션 저장 내용 SHA가 통합 전후 모두 일치**함을 확인했다. 사용자 세션을 새 실행 시험의 입력으로 사용하지 않았다. 공개 소스의 제외 범위는 `.env`, 모델 가중치, SQLite, 실행 로그, 업로드 원본 PDF, 사용자 인터뷰 기록이다.

기존 DB를 유지한 채 새 SOUL의 private DB로 SQLite backup을 수행했고, 두 DB의 17개 payload가 모두 일치함을 다시 확인했다. 기존 실행기를 종료하고 Windows SOUL 런처를 실제 실행했다. frontend 8000의 같은 origin API → backend 8001 → 기존 Qwen 8080에서 health qwen/ok 및 기존 최근 세션 복원에 성공했다. 기존 모델 프로세스는 유지했다. 이전 창의 미전송 입력도 로컬 private 작업 파일에 보존한 뒤 화면을 새로고침했다.

human Gold와 고객 행동자료가 없어 성능 점수는 제공하지 않는다. synthetic eval 3건의 관찰 불가능 PSV-9 점수는 null이며 실제 인간 평가를 대체하지 않는다.
