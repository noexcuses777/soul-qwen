# 대화 프로토콜 3 — 내용에 반응하는 라운지

2026-10-03의 자동 진행 옵션 설계다. 현재 기본은 docs/13의 사용자 진행 v4이며 이 문서는 자동 진행을 선택했을 때 docs/03의 고정 라운드를 대체한다. 평가 A/B/C/D의 통제 조건과 기존 protocol_version=2 세션은 유지한다.

## 근거와 적용 범위

- NSona 원문 pp.36–38: Turn-taking/Adjacency pairs, 수신자 지정, 다음 발화 예측과 chat_summary_buffer. Who/What/How와 독립 카드/컨텍스트를 유지한다. NSona 전체 성능을 재현했다고 주장하지 않는다.
- Sacks, Schegloff & Jefferson (1974), Language 50(4), 696–735, [원문](https://pure.mpg.de/pubman/item/item_2376846_3/component/file_2376845/Sacks_1974_simplest_systematics.pdf): 현재 화자의 다음 화자 지정과 발화 완료 지점을 구별한다. 질문 수신자의 답변을 먼저 받고 그 다음 반응을 선정한다. 인간 일상 대화의 기술적 분석이며 AI 효과의 보증이 아니다.
- Schegloff, Jefferson & Sacks (1977), Language 53(2), 361–382, [저자 아카이브](https://www.conversationanalysis.org/schegloff-publication-archive/): 오해/모순은 남이 대신 고치기보다 원 화자가 설명·정정할 기회를 먼저 받는다. 실제 시스템은 의미 오류 탐지의 완전성을 보장하지 않는다.
- Schegloff & Sacks (1973), Semiotica 8(4), 289–327, [원문](https://web.stanford.edu/~eckert/Courses/l1562018/Readings/SchegloffSacks1973.pdf): 종료 예고, 남은 주제 제시 기회, 종료를 구분한다. 해결되지 않은 질문은 기록하고 끝낸다.
- Baltaji et al. (2024), C3NLP, [논문](https://aclanthology.org/2024.c3nlp-1.2/): LLM 집단 대화의 동조·역할 혼동 위험. 비공개 전/후 의견, 근거 없는 입장 변경 억제, 역할 귀속, 제한된 상호작용을 유지한다. 연구 모델/문화 과제의 결과를 Qwen 창업 검증 효과로 일반화하지 않는다.
- Wang et al. (2024), ACL, [논문](https://aclanthology.org/2024.acl-long.331/): 다중 에이전트 토론이 강한 단일 에이전트보다 항상 낫지는 않았다. 자동/직접/상호 대화 선택과 비용 상한을 둔다. 해당 추론 실험은 고객 리서치의 유효성을 증명하지 않는다.

## 시작, 중간, 종료

1. 비공개 사전 의견으로 독립 판단을 확보한다. 진행자가 목적, 가설임, 모른다고 답해도 됨을 알린다.
2. 문제·해법·타인 조건 비교·조건 차이·도입/지불·실패 조건은 **확인할 의제**다. 고정 인원 순회 라운드가 아니다. 첫 문제 발화 이후 다른 사람의 실제 공개 발화에 반응할 수 있다.
   시작은 문제 확인이다. 이후 의제 순서도 고정하지 않는다. 최근 공개 발화와 남은 조건에서 예산/도입, 실패/중단, 비교/역할, 오해/차이, 효과/신뢰 단서를 세어 아직 다루지 않은 의제를 선택한다. 동률은 기본 의제 순서로 결정한다. 이 키워드 기반 라우팅은 비용을 줄이는 명시적 구현 선택이며 자연어 의미 이해의 완전성을 주장하지 않는다.
3. 한 모델을 순차 호출한다. 구조화된 발화 행위(answer/question/clarify/disagree/agree/close), 수신자, 확인 질문으로 다음 차례를 계산한다. 이는 오류 가능한 모델 신호다. 지정된 질문→답/정정 우선, 그 다음 relevance + disagreement + direct mention + unresolved - recent speaking penalty를 적용한다.
4. 질문/정정에는 원 화자가 답할 기회를 준다. 동의에도 자기 조건의 공통점/차이를 말한다. 새로운 경험, 가짜 갈등, 강제 찬반은 금지한다. 한 의제의 상호 응답 깊이는 최대 3으로 제한해 다음 의제로 이동한다.
   새 의제 첫 발화는 공개 발화가 가장 적은 참여자들 중 score로 선정한다. 수신자가 지정된 답변 차례에는 이 제한을 적용하지 않는다. 확인 질문의 정규화 문자 3-gram Dice 유사도 ≥0.6이 최근8개 공개 질문과 겹치면 다시 묻지 않고 미해결로 남긴다. 이는 저비용 반복 억제 휴리스틱이며 논문에서 증명된 임계값이나 의미적 동일성 판정이 아니다. 실제 Qwen 최초 시도에서 발화 편중/반복을 발견해 추가한 제약이다.
5. 제품 group 기본 상한 18개, 종료 확인을 위해 참여자 수만큼 예약한다. 보통 12–18개를 예상하지만 모든 의제가 확인되고 응답 대기가 없으면 더 일찍 종료한다. 마지막 확인에서 새 문제를 제시하면 남은 예산 안에서 한 번 더 설명할 기회를 준다. 아직 도입하지 않은 의제에도 최소 한 차례를 예약한다. 한 참여자일 때는 자기 조건 확인이며 페르소나 간 상호작용이라고 부르지 않는다.
6. 종료 이유(의제 확인/예산 상한)를 공개한다. 개인별 종료 확인 → 비공개 사후 의견 → 리포트. 미해결 질문은 리포트/상태에 남긴다. 종료는 합의나 시장 검증 성공을 의미하지 않는다.

## 추가 질문

- 직접 답변: 지정 또는 가장 관련 있는 한 명, 1발화. 명확한 정보 확인과 비용 절약에 사용한다.
- 상호 대화: 첫 답변 → 다른 참여자의 조건 비교/질문 → 필요하면 원 화자의 답/정정, 최대 4발화. 관련된 반응이 없으면 일찍 종료한다.
- 자동(기본): 첫 답변의 미해결 조건, 질문/정정/이견이 있을 때 상호 반응을 연다. 충분한 답이면 종료한다. 단순 질문 문장 길이로 분류하지 않는다.
- 질문에 특정 참여자를 지정하면 그 사람이 먼저 답한다. 다른 사람이 대신 자기 경험처럼 답하지 않는다. 후속 모델 실패 시 동일 요청으로 저장된 다음 차례부터 재개한다. 다른 질문은 미완료 요청이 끝난 뒤에 받는다.

## 구현/화면/검증

- 명시적 컨트롤러 + 저장된 runtime(step, agenda index, pending recipient, depth, close reason); 매 차례 모델 그래프/판정 호출 없음. 읽기/재개는 기존 발화를 재생성하지 않는다.
- 최근 6공개/4개인 발화와 출처 있는 요약만 사용. 답할 공개 발화는 최근 버퍼에서 선택하고 reply_to는 서버가 연결한다. 비공개 전/후 내용은 공개 컨텍스트에 주입하지 않는다.
- 하나의 큰 채팅창: 진행자 안내/창업자 질문/참여자별 말풍선/답글 미리보기/생성 중 표시/하단 질문 입력. 비공개 의견은 별도 접힌 상세 정보에 둔다. 인위적인 인간 응답 지연은 넣지 않는다.
- 회귀: 1–3명, 수신자 우선, 답글 귀속, 깊이/전체 예산, 종료, 실패 재개, 추가 질문 모드, private leakage, 기존 v2/eval 보존. 실제 Qwen smoke는 실행 가능성만 검증한다. 객관적 품질 우위는 docs/07의 실제 인터뷰+인간 평가에 v3 대조군을 추가해 검증한다.
