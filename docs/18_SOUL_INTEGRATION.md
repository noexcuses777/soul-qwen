# SOUL 프론트엔드 × Qwen 통합 계약

2026-10-05. 화면 후속 변경은 [업데이트 계약](19_FRONTEND_UPDATE.md)을 함께 적용한다. 최신 사용자 요구 > 이 통합 계약 > 기존 v5 문서 > 이전 설계 순서로 적용한다.

## 가져온 화면과 제외한 실행 경로

`jiwooks/SW-Festival`의 main `9f4337e`를 기준으로 한다. `feat/soul-rebase`, `feat/chat`, `feat/idea-input`, `feat/targets-screen`은 파일 목록을 비교했다. main에는 아이디어, 타깃 생성·선택, 비교, 그룹·개별 대화, 리포트, 빈 상태·로딩·오류의 SOUL 화면이 반영되어 있다. 기존 프론트엔드만 sparse checkout했다. 기존 `/api/chat` 구현 및 다른 모델 파일은 읽거나 실행하지 않는다. 모델 접근은 보존한 Python Qwen 클라이언트 하나에 한정한다. 다른 모델의 가중치·학습·추론·환경설정은 사용하지 않는다.

화면의 샘플 persona·quote·대화·리포트·선택된 세 명·가짜 타이머·의무 반대자 플래그는 실제 경로에서 제거한다. Qwen 실패를 mock 결과로 대체하지 않는다. 명시적으로 시작한 mock 모드만 합성 실행 점검이다. 학습 가중치를 새로 생성하거나 혼합하지 않는다. 기존 프로젝트의 구조화 프롬프트, 독립 문맥, 생성·검사·재생성, 대화 제어와 평가 준비를 그대로 사용한다.

## 화면별 연결

| 화면 | 데이터·행동 |
|---|---|
| 아이디어 | Q1·Q2·Q3-1·Q3-2·Q4-1·Q5 → POST `/api/sessions`; Q3/Q4는 제목; API와 동일한 글자 수 |
| 타깃 | 6~8개 원 후보를 검사하고 중복 대조 조건을 제거한 실제 WHO 세그먼트(최소 3개). 최대 3개 선택/수정/직접 추가 → `/select`. 각 생성 카드 별도 검증 |
| 한눈에 보기 | 선택 카드의 Identity/Context, Problem, Decision, Goals, Evidence, Style, Immutable Core. UNKNOWN은 미확인 |
| 대화 | 동일한 일반 채팅칸 → `/ask`. 처음 요청의 private pre, 모든 선택자의 독립 기여, 조건 기반 상호응답. GET 폴링으로 공개 발화만 표시 |
| 특정 참여자 질문 | `/ask`의 persona_id + direct. 현 프로토콜의 공개 대화 기록이며 비공개 DM으로 주장하지 않는다 |
| 리포트 | `/finish`의 private post·기존 8개 인사이트 + GET `/report-view`의 세션 기반 화면. 인용으로 원 발화 추적 |
| 이어 묻기 | 리포트 질문을 기존 채팅칸에 채움. 사용자가 전송. 같은 세션에 계속 대화하며 기존 리포트 stale 표시 |
| 다른 타깃 | 기존 기록을 보존하고 아이디어 초안으로 새로운 세션 생성 |

브라우저에는 현재 세션 ID, 아이디어 초안, 후보 편집 초안과 선택 ID를 저장한다. 서버 SQLite가 카드·전체 기록·인사이트·감사의 기준이다. 이름 옆에는 이용자 예시(세그먼트)만 표시하며 역할 표시 선택기는 없다. 다른 질문이나 타깃으로 실패한 작업을 몰래 재개하지 않는다.

## 리포트 근거와 집계

`Soul_분석리포트.pdf` 전체 1페이지와 `05-report.html` 전체를 읽고 배치를 참고했다. 원본은 고정 1440×2340 시안으로 API·버튼 동작이 없으며, 샘플 신규 인사이트 수·전원 판단 일부가 맞지 않는다. 샘플 이름·금액·수치·주장은 복사하지 않는다. 반응형 카드와 내용에 따른 높이로 구현한다.

기존 `Report.sections` 8개와 출처 검증은 유지한다. `report-view`는 해당 snapshot의 공개 발화와 실제 카드, 기존 인사이트로 구성한다. 인용 없는 시장 추론이나 새 인사이트를 presenter가 발명하지 않는다. 쟁점 수, 입장 표현 차이, 같은 쟁점에서 이유를 밝힌 입장 표현 변화, 대화 인사이트 수는 검증된 배열에서 계산한다. 조건부/미확인은 찬성표에 합산하지 않는다. 실수요·구매확률·PMF·PSV-9·인간 유사 정확도는 산출하지 않는다. 전원 합의는 모든 선택자의 명시적 긍정 및 인용을 확인해야 한다. 변화의 인과관계나 분위기 동조 제거를 입증했다고 주장하지 않는다.

리포트 생성 시간은 성공 시 저장하고 캐시 조회마다 바꾸지 않는다. 시간 정보가 없는 이전 리포트는 미기록으로 남긴다. 모델 호출 지연 합계를 인터뷰 총 소요시간으로 표시하지 않는다. 인사이트·발화의 L0~4 및 hypothesis 상태를 유지한다. JSON·텍스트 내려받기, 인쇄/PDF 저장, 질문 복사, 이어 묻기와 타깃 재선택을 실제 기능으로 연결한다.

## 실행과 보존

Next.js :8000 → 동일 출처 `/api/*` → FastAPI :8001 → Qwen llama.cpp :8080. 한 개 shared model, 최대 세 independent persona contexts. Next proxy timeout 30분; 모델별 개별 호출 제한과 토큰 packing은 기존대로 유지한다. 이는 속도 향상 측정이 아니라 불필요한 네트워크 중단 방지다.

기존 Persona Studio 저장소·사용자 DB를 덮어쓰지 않는다. 시험은 별도 DB와 포트로 수행한다. 공개 브랜치에는 소스·설계·합성 평가 예시·테스트만 포함하며 원본 PDF·사용자 DB·개인 인터뷰 기록·모델 가중치·.env·실행 로그를 넣지 않는다. 문서에 남은 이전 로컬 `examples/` 증거 경로는 역사 기록이며 공개 파일의 존재나 이번 검증 결과를 뜻하지 않는다.

Qwen 실제 실행/브라우저/회귀검증/미확인 항목은 `STATUS.md`와 `docs/SOUL_VERIFICATION.md`로 구분한다. Windows NVIDIA 8GB와 Mac M4 16GB의 실행 문서는 제공하되 현재 컴퓨터 실행만으로 해당 하드웨어의 성능을 검증했다고 하지 않는다.
