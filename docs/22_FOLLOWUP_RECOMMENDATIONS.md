# SOUL 후속 질문 추천 — protocol 6 보완 (2026-10-12)

## 발견한 문제

기존 채팅 화면은 마지막 원질문과 `remaining_issues`의 앞 두 항목을 고정 문장에 넣고 500자에서 잘랐다. 후속 질문이 새 원질문이 되면 그 문장을 다시 감싸므로 질문이 중첩되고, 앞부분만 남거나 같은 미확인 항목을 반복할 수 있었다. 버튼은 실제 자료가 필요한 종료에도 같은 문장을 만들었다. 이는 현재 대화에서 더 살펴볼 필요가 있는지 판단하는 추천이 아니었다.

과거 `remaining_issues`는 해당 질문 묶음의 모든 발언에서 모은 기록이어서 뒤 발언에서 설명되거나 수정된 항목도 들어 있을 수 있다. 새 질문 묶음의 표시 목록은 각 화자의 최신 답변을 기준으로 계산한다. 기존 기록을 삭제하지 않고 최신 공개 답변과 함께 검토하며, 목록에 남아 있다는 이유만으로 아직 미해결이라고 판단하지 않는다.

## 제품 계약

사용자가 후속 질문 추천을 요청할 때 공유 Qwen 모델이 최신 공개 대화와 카드의 판단 조건을 검토한다. 추천은 질문 하나를 채팅 입력칸에 넣는 동작이고, 전송은 사용자가 결정한다. 질문을 자동으로 보내거나 페르소나 대화를 자동 재개하지 않는다. 다른 모델이나 별도 임베딩 모델을 추가하지 않는다.

추천에는 다음 세 결과가 있다.

| 결과 | 판단 기준 | 사용자에게 제공할 내용 |
| --- | --- | --- |
| `discussion` | 카드로 조건부 추론할 수 있고, 이전에 답하거나 제안하지 않은 판단 변수·상충 조건이 실제 공개 발언에 나타남 | 새 질문 하나, 지금 질문할 이유, 연결한 공개 발언 |
| `needs_evidence` | 추가 판단이 실제 고객의 행동·경험·가격·성능 측정 등의 새 자료에 달림 | 어떤 자료가 왜 필요한지, 사용자가 다음에 확인할 항목. 페르소나에게 답하게 할 질문은 만들지 않음 |
| `no_new_question` | 조건이 이미 설명되었거나, 반복·근거 부족으로 유용한 확장을 식별하지 못함 | 지금 더 추천할 질문이 없다는 설명. 사용자는 같은 입력칸에서 자유롭게 질문 가능 |

예를 들어 “타깃 추천의 실제 정확도”와 “대화 시나리오의 실제 유용성”은 페르소나를 다시 토론시킨다고 확인되지 않는다. 실제 고객 타깃과의 비교, 사용자의 과제 수행 관찰, 인터뷰 결과 등이 필요한 외부 검증이다. 반면 실제 공개 발언에서 “편리해도 기존 질문 준비 과정을 대체하지 못하면 추가 업무”라는 새 조건이 나왔다면, 카드의 현재 대안과 연결해 대체/추가 업무일 때 판단이 어떻게 달라지는지 조건부로 탐색할 수 있다. 이는 생성된 가설이며 효과 측정 결과가 아니다.

## 입력과 근거 경계

- 현재 아이디어의 요약, 선택한 카드의 역할·현재 대안·도입 장벽·판단 규칙, 최신 완료 질문의 원질문과 종료 이유를 제공한다.
- 해당 질문의 유효한 공개 발언과 각 화자의 마지막 공개 답변을 우선 제공한다. 이전 발언은 해당 주장에 대한 설명·수정 여부를 살펴보기 위한 맥락이다.
- private pre/post, 다른 사람의 비공개 상태, 보류된 발언의 원문은 추천 근거로 쓰지 않는다.
- 모델은 추천을 뒷받침하는 공개 발언 ID와 탐색할 조건, 새로 얻고자 하는 답의 종류를 명시한다. 서버는 ID가 실제로 존재하고 공개·유효한 발언인지 확인한다.
- 카드나 대화가 새로운 시장 사실을 증명하는 것은 아니다. 근거 수준은 대화 횟수나 합의로 올라가지 않는다. 없던 가격·빈도·성능 수치, 실제 경험, 확정 구매 의사를 전제로 질문하지 않는다.
- 출력은 500자 이하의 완결된 질문이어야 한다. 넘치는 질문을 화면에서 자르는 대신 거부·교정하거나 추천을 보류한다.

## 중복과 의미 있는 확장의 검증

추천 모델에는 이미 물어본 질문, 이미 제안한 질문, 공개 페르소나 발언에 포함된 후속 질문을 제외 목록으로 제공한다. 서버도 모든 저장된 질문/제안 기록과 비교한다. 모델에 보내는 맥락을 줄여도 서버 검사의 제외 이력은 최근 몇 개로 제한하지 않는다. 자료 확인 안내에서도 제외 이력을 검사하고 질문을 설명문으로 반복 표시하지 않는다.

1. 유니코드 NFKC, 대소문자, 공백·문장부호를 정규화해 동일 질문을 거부한다. 이전 원질문을 인용하는 겉포장이 달라도 중복으로 판단한다.
2. 문자열 유사도와 한글 문자 n-gram 겹침으로 작은 표현 변경, 긴 인용·접두어, 잘린 원질문의 재사용을 탐지한다. 수치 문턱은 제품 휴리스틱이며 한국어 의미를 완벽하게 판정하는 척도가 아니다.
3. 질문의 쟁점, 비교 대상, 새 조건, 원하는 답의 종류를 함께 검토한다. 같은 조건에서 같은 선택을 다시 묻는 질문은 어휘만 달라도 새 추천이 아니다. 넓은 주제가 같아도 실제로 아직 설명하지 않은 다른 조건을 묻는 질문은 허용할 수 있다.
4. “더 구체적으로”, “다시 비교해 주세요” 같은 표현만 추가한 질문, 이전 질문 전체를 감싼 질문, 이미 외부 검증이 필요하다고 결론 난 항목을 가상 상대에게 다시 묻는 질문은 거부한다.
5. 새 조건이나 근거를 확인하지 못하면 질문을 억지로 만들지 않는다. 부정확한 추천이 반복되는 경우 `no_new_question` 또는 `needs_evidence`로 반환한다.

이 검사는 반복 위험을 줄이지만 모든 의미상 동의어를 완벽하게 탐지한다는 품질 보장은 아니다. 모호한 경우에는 새 질문을 만들어 내기보다 추천을 보류한다. 사용자의 직접 입력은 추천 이력과 같더라도 금지하지 않는다. 동일한 질문을 다시 묻는 의도는 사용자가 결정할 수 있다.

## 비용·저장·오류 처리

추천은 매 발언 뒤 자동 호출하지 않고 요청할 때만 실행한다. 현재 질문 ID·공개 대화 revision·카드 조건·제외 이력에 연결해 결과를 저장한다. 같은 상태에서 다시 누르면 저장된 결과를 사용하고 입력칸에 같은 질문을 중복 삽입하지 않는다. 새 답변이 생기거나 이미 제안한 질문을 보내면 이전 결과를 새 대화의 추천으로 재사용하지 않는다.

생성과 검증 교정에는 유한한 호출 상한을 둔다. 부적절한 답을 받을 때 무한히 재생성하거나 고정 질문으로 대체하지 않는다. 추천 사용량은 실제 페르소나 발언 사용량과 구분하고, 추천만 요청해도 발언 수·원질문·리포트 revision을 늘리지 않는다. 서버가 바뀌거나 같은 요청이 겹쳐도 저장 상태를 확인하고 중복 생성을 피한다.

구현은 최대 3개 후보를 한 번 계획하고, 유효한 토론 후보가 있을 때만 별도 프롬프트로 의미·답변 가능성을 한 번 검토한다. 각 호출의 기존 JSON 교정도 유한하며 추천 실패 시 고정 질문으로 대체하지 않는다. 모델 제외 목록은 중복을 합친 최대 32개 질문/제안까지 제공한다. 그보다 길어 전체 의미 비교를 안전하게 할 수 없으면 새 질문을 인증하지 않고 보류한다. 서버 문자열 검사는 전체 이력을 유지한다. 같은 공개 revision·질문 ID·카드 fingerprint·아이디어/자료에서 같은 요청은 캐시하며, 추천이 대화에 전달되거나 조건/자료가 바뀌면 새 상태를 평가한다.

모델 연결·형식 검사가 실패하면 오류를 표시하고 직접 질문 입력을 유지한다. 실패한 추천을 성공 결과로 저장하지 않는다. 추천과 실제 대화 요청을 분리해 추천 실패 때문에 기존 채팅이 막히지 않게 한다.

## 회귀 검증 항목

- 같은 문장, 공백/문장부호 차이, 원질문 인용, 500자 잘림, 한국어 유사 표현, 여러 질문 전의 반복을 거부한다.
- 이미 제안했지만 아직 보내지 않은 질문도 새 추천 제외 목록에 남는다. 동일 revision의 재요청은 호출 비용 없이 기존 결과를 보여 준다.
- 제안 질문을 보낸 뒤 새 대화에서는 그 질문을 반복하지 않는다. 다른 카드 조건이나 공개 쟁점에 따른 새 질문은 허용한다.
- 최신 발언에서 설명·수정·종료된 과거 쟁점을 `remaining_issues`에 남았다는 이유로 되살리지 않는다.
- 실제 정확도·유용성·구매·가격 검증은 새 관측 자료가 필요함을 표시한다. 유용한 새 쟁점이 없으면 추천 없음으로 반환한다.
- 없는 발언 ID, private 발언 ID, 보류된 발언, 없는 카드 조건, 미확인 수치 전제를 거부한다.
- stale revision 요청, 모델 오류, 형식 오류, 중복 클릭에서도 기존 발언과 리포트 snapshot을 바꾸지 않는다. 직접 메시지는 계속 보낼 수 있다.
- 추천 결과를 받아도 자동으로 대화가 시작되지 않는다. 사용자의 전송 후에만 새 질문 묶음이 생성된다.

검사 결과는 실제 실행 뒤 STATUS.md에 기록한다. 합성 검사는 계약·연결 검증이며 실제 고객 인사이트 품질이나 Qwen의 일반적인 추천 정확도 평가가 아니다. 대화 확장의 연구 근거와 한계는 [21_DIALOGUE_DEPTH.md](21_DIALOGUE_DEPTH.md)를 따른다.
