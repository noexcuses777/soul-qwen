# Persona Lounge v4 — 설계 고정 (2026-10-03)

2026-10-04: 이 문서는 이전 v4 설계 이력이다. 현재 동작은 [v5 기본 채팅 설계](15_CONTINUOUS_CHAT_REVISION.md)가 우선한다. 이름+예시군만 표시하고, 선택 후 같은 입력칸에서 전원 기여·조건 비교를 이어간다. 표시 선택/질문4턴/전체60턴/강제closing/완료 뒤 자동리포트 규칙은 v5에서 대체됐다.

이 문서를 구현 전에 고정했다. v2는 A–D 통제 실험, v3는 기존 자동 인터뷰와 저장 세션 호환용이다. 새 화면의 기본은 **사용자 질문 + Qwen 질문 추천 + 제한된 자율 상호작용**이다. 근거와 NSona 전체 대응표는 [14번 문서](14_NSONA_RESEARCH_AUDIT.md)에 있다.

## 이름 옆 표시

기본은 ③ 예시군 + 역할군. 이름은 굵게, 역할은 작은 배지, 예시군은 다음 줄에 둔다. 예: `김하늘 [구매담당] / B2B 기관 라이선스 구매자`. 이름은 가상 별칭이며 성별·나이·경력·성격을 암시하는 입력으로 사용하지 않는다. 표시 정보는 immutable core 바깥에 둔다. 역할은 카드의 실제 buying_role 문구를 사용하고, 모르면 `역할 미확인`이다. 구매담당과 결정권자·지불자를 자동으로 동일시하지 않는다. 한 사람이 복수 역할이면 원문을 보존한다.

①은 업무 맥락을 잘 보여주지만 결정 권한을 읽기 어렵고, ②는 권한을 빨리 읽을 수 있지만 같은 역할의 서로 다른 상황을 구분하기 어렵다. ③은 두 정보를 모두 보존한다. 이 선택은 정보 손실을 줄이는 설계 판단이다. 세 방식의 사용자 성과를 직접 비교한 논문이 있다고 주장하지 않는다. 화면에서 세 표시를 바꾸어 비교할 수 있다. 이름 클릭 시 Who(정체성·상황), What(대안·문제·결정 조건), How(발화 스타일), 판단 가설·근거·미확인 항목을 펼친다. 별칭은 직접 수정 가능하다.

## 대화 시작·중간·종료

1. 타깃 선택과 별도 검사 후 Qwen이 카드/아이디어에 맞는 중립적 질문 6개를 한 번 추천한다. 질문은 six-topic coverage tag, 왜 확인할지, 특정 참여자를 포함한다. 추천 칩은 입력칸에 넣기만 하며 사용자가 보내야 시작한다. 창업자 대신 구매 의사를 유도하는 질문은 금지한다.
2. 기본 `직접 질문 + 추천`: 라운지 열기 → 각자의 private pre를 서로 공개하지 않고 수집 → WAITING. 사용자가 질문을 보내면 하나의 thread가 열린다. 사용자는 자유롭게 순서·질문·응답 방식(auto/direct/interactive)을 정한다. 여섯 주제는 확인 범위이며 고정 질문 순서가 아니다.
3. 대안 `중재자 자동 진행`: 기존 v3의 내용 반응형 진행을 명시적으로 선택한다. 자동 진행에는 18개 공개 발화 상한이 있다. 임의의 LLM graph 실행이나 외부 검색 호출은 하지 않는다.
4. Thread 첫 화자는 관련성·조건 차이·직접 지목·미해결 문제·최근 발화 패널티로 고른다. 지명된 수신자의 답변이 최우선이다. 질문→답, 오해→정정, 주장→조건 비교의 연결을 `reply_to`, `addressed_to`, thread ID로 저장한다. 오해를 지적하면 원래 발화자에게 설명 기회를 준다. direct는 한 답변만, auto는 필요한 질문/정정/조건 비교만, interactive는 최소 한 명의 다른 관점을 비교한다. 세 사람이 항상 차례대로 말하거나 항상 서로 반대하지 않는다.
5. Thread 당 최대 4개 응답, 동일 질문 반복/의미 있는 후속 쟁점 부재/close act/상한 도달 시 사용자에게 차례를 돌려준다. 응답 연결이 남으면 해결한 척하지 않고 다음 질문에 쓸 미해결 항목으로 보존한다. 새 질문에는 해당 thread의 최근 발화만 넣고, 이전 thread는 귀속된 요약으로 남긴다. 특정 응답의 부모는 입력 context에 유지한다. 남의 private pre/post는 공유하지 않는다.
6. 사용자가 `대화 마무리·리포트`를 누르면 pre-closing(각자 핵심 정정·남은 조건 1개) → private post → 8-section report → COMPLETE. 기다리는 동안 저절로 시장 결론을 내리지 않는다. 한 세션은 공개 발화 60개 상한이며 상한에서는 종료 버튼으로 정리한다. 완료 후 추가 질문은 가능하지만 비용 상한은 동일하다. 종료·질문 중 실패는 완료된 발화와 cursor를 저장하고 같은 동작으로 재개한다.
7. 타이핑 중인 인간에게 실시간으로 끼어들지 않는다. 텍스트 전송/모델 응답 완성 시에만 차례를 넘기며 가짜 지연·가짜 실시간 타이핑을 넣지 않는다. 1974년 turn-taking 규칙은 이 경계와 지명 우선의 근거이며 오디오 TRP 예측 구현을 의미하지 않는다.

## 깊이가 있는 페르소나와 사실 경계

기존 8개 core block은 유지한다. 실제 인구통계·경험·예산·역사는 정확한 원문 anchor가 없으면 UNKNOWN이다. 이를 완화하는 대신 `reasoning_rules`를 별도로 추가한다: 조건(trigger) → 중요하게 볼 가치(value) → tradeoff → 조건부 판단(conditional_choice) → 근거인 카드 필드(basis_fields) → 미확인 조건. Qwen이 1~2개를 생성하고 Validator가 별도로 확인한다. **모든 rule은 해석 가설**이며 경험이나 심리 특성이 확인됐다는 의미가 아니다. 실증 자료가 있다면 evidence_ids를 이어 붙여도 해석 자체는 가설이다.

Timeline은 근거에 있는 사건 quote/source/시점(없으면 UNKNOWN)을 보여준다. 사건이 없으면 빈 배열이다. 사건에서 의미·동기를 추론할 때 rule로 분리한다. 선형 인생사를 억지로 만들지 않는다. Session stance 변경은 이유를 기록하지만 immutable values/role은 바뀌지 않는다. 이름·표시방식만 바꿔도 추론 카드와 stance가 바뀌면 안 된다.

응답은 자신이 사용한 rule ID를 남긴다. 공개 말은 짧고 자연스럽게, 접힌 근거에는 조건부 판단과 rule을 보인다. rule ID·source ID는 서버가 검증한다. 잘못된 출처/경험 확정/구매 확정에 대한 제한적 문장 검사와 교정은 방어 장치이며 한국어 의미 전체를 판정하는 도구는 아니다. 실제 응답을 사람이 PSV-9와 함께 검토해야 한다.

## 비용과 확인 계획

한 Qwen을 공유하고 모든 persona context는 분리한다. 질문 추천은 1회, rule은 카드 생성 출력에 함께 넣어 별도 모델 상시 구동을 추가하지 않는다. WAITING에서는 report를 매 질문마다 재생성하지 않고 종료 시 한 번 생성한다. 완료 후 질문에만 기존 report를 갱신한다. 히스토리·질문·출력은 기존 tokenizer budget guard에 포함한다.

구조 테스트: 1~3인, 이름 변경/core 불변, rule 근거/UNKNOWN, timeline 원문, thread 경계, 지명/정정/반복/조기 종료, resume 중복 방지, private 격리, 자동 모드 호환, 60 발화 상한, API/UI flow. 실제 Qwen으로 추천→질문→후속→종료를 실행해 연결·스키마·문맥·지연을 확인한다. 기능 통과를 시장 검증이나 인간 같은 대화 품질 통과로 부르지 않는다.

사용성 실험: 예시군/역할군/둘 다 조건을 참가자 내 무작위 순서로 비교하고 누가 쓰고/결정하고/지불하는지 식별 정확도·시간·이해도·선호를 기록한다. 시작 방식도 직접/자동/추천 세 조건에서 질문 수정율·주도감·유효 후속 질문·시간·PSV-9·실제 인터뷰 usefulness를 비교한다. 기존 A–D는 유지하고 v4를 별도 E 조건으로 추가한다. 동일 모델·아이디어·카드·질문 범위·총 출력 token 예산을 맞춘 뒤 judge와 human을 함께 사용한다.


마무리 확인은 다른 참여자에게 새 질문을 여는 단계가 아니다. 각자의 카드/판단 조건을 우선하며 공개 직전 발화는 그 단계의 모델 문맥에서 제외한다. 사후 의견에는 그 사람의 비공개 사전 의견과 최근 동료의 조건을 구분해 전달한다. 동일 문장 반복은 제한적 유사도 검사로 최대1회 추가 호출하며 원문/교정 flag를 보존한다. UNKNOWN 순환이나 의미상 동조를 완전히 검출한다고 주장하지 않는다.
